# Surika：以 Skill 为主要交付形态的重新定位研究与提案

日期：2026-11-15。状态：研究与建议，未替代现有产品决策与 ADR，未启动实现或安装外部 skill。

后续澄清：用户要求的是成熟有效的方法论，不要求原创或独有。方法论的推导、选择与实施以[成熟教学方法论：第一性原理推导与落地](成熟教学方法论_第一性原理推导与落地.md)为后续提案；[教学 Skills 原文对照](教学Skills方法论原文对照.md)进一步核对了附件中的规则，补充并修正本篇对部分技能的概括。本篇保留为产品形态讨论背景。

## 结论

建议把 Surika 定位为：**面向使用 AI 编程者的持续学习伙伴，以 skill 嵌入现有 Agent 工作环境，帮助学习者从具体问题出发，形成能够解释、验证并用于新情境的技术理解。**

首版交付一个 skill 包、少量经过核验的 Go 学习材料、可修正的文件记忆和教学行为评估案例。对话是主要界面；参考卡、图示和 HTML 是按需材料。先验证教学价值，再决定是否需要独立界面。

这是产品假设，不是教育研究已经证明的结论。Skill 减少界面、模型客户端和配置维护，却把执行权限、上下文管理、工具可用性和部分体验一致性交给宿主；成本是转移和减少，不是消失。

后三者属于值得研究的小众样本，不应包装为“目前最流行”。`teach-impeccable` 虽然名称含 teach，主要是让 Agent 记录设计上下文，不属于教人学习的同类产品。

竞争判断：再做一个“会讲解、会生成教程”的通用 skill，差异很薄。Surika 更值得验证的是：**能否在多次探索中保留可信的学习线索，并据此提供恰当的下一步，让人逐渐减少帮助也能理解和判断。**

## 3. teach 与 rederive 应怎样组合

本机原文：[teach](/Users/linzhikai/.agents/skills/teach/SKILL.md)、[rederive](/Users/linzhikai/.agents/skills/rederive/SKILL.md)。本次将其作为研究对象，不执行课程初始化、仓库推导或子 Agent 教学流程。

### teach：借鉴连续性，调整强制要求

值得保留：学习目标连接实际用途；课程与速查材料分工；跨会话记录；检索与间隔练习；共同术语；资源有用途注释。

需要调整：

- **使命可以逐渐形成。**先记录用户的问题或暂定方向，不清楚时给一个可体验的起点。避免与 Surika 已确认的低门槛入口冲突。
- **学习活动才是核心单位。**HTML 课件适用于需要反复操作或打印的场景，几句解释和一次代码修改也可以形成完整活动。
- **不能精确“计算最近发展区”。**历史记录只能支持暂定的难度判断，下一次表现可能推翻它。
- **自述与表现需要分栏。**本机 learning-record 模板允许记录自述，Evidence 又是可选项；Surika 对能力推断必须要求具体表现和帮助条件，缺证据就标记未验证。
- **测验选项应自然且没有形式暗示。**等字数可以是编辑技巧，不应成为机械规则，以免为了长度制造别扭或无效选项。
- **自包含 HTML 与外链共享 assets 存在交付张力。**若追求单文件分享，应在需要时打包；不在首版建设通用课件流水线。

### rederive：借鉴问题链，放宽教学僵化

值得保留：先给问题再引入技术名称；逐个增加真实约束；允许比原实现更好的方案；从证据和源码理解机制；记录哪里需要提示。

需要调整：

- **不能把“永不揭示答案”设为通用原则。**缺少符号、基础规则或背景时，应直接示范；用户明确要解释时也应允许切换。
- **原实现不是唯一正确答案。**达到目标约束即可讨论权衡，不要求学习者猜中作者的设计。
- **源码能说明机制，未必证明动机。**明确区分“代码这样做”“提交/设计文档写明原因”“Agent 推测原因”。
- **先修不足时缩小问题。**不把零基础学习者直接放进完整系统设计，也不无限向下补基础。
- **一个问题一次推进，但整体方向可见。**默认不展示长试卷；用户想看路线时可展示，不继承“永不列出问题”的限制。

建议组合方式：teach 提供连续学习的组织方式，rederive 提供一种推导活动，Surika 自己负责何时解释、何时练习、如何记录证据与如何续接。不要直接拼接两份 SKILL.md：它们对开始条件、输出形态和回答策略有真实冲突。

## 4. 教育研究如何转化为行为

下表区分研究/框架与产品推论。它们支持教学设计方向，不证明具体 Surika skill 已有效。

| 方法与来源 | 可借鉴的核心 | Surika 的产品推论 | 边界 |
|---|---|---|---|
| [认知学徒制：Collins、Brown、Holum](https://www.aft.org/ae/winter1991/collins_brown_holum) | 示范、指导、支架支持，以及表达、反思和探索 | 先展示必要的解题依据，再让用户参与，逐步减少帮助 | 是设计框架，不是固定六步课程；不是要求模型输出内部思维链 |
| [CMU Eberly 学习原则](https://www.cmu.edu/teaching/principles/learning.html) | 先前知识可能帮助或妨碍学习；目标练习需要针对性反馈 | 用小表现了解起点，反馈具体到这次任务，连接概念与用途 | 一次回答不能识别人的全部水平 |
| [IES 学习与教学实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1) | 分散学习、交替示例与解题、主动提取、深层解释问题 | 学过后换例子，后续再用；必要时先看示范再尝试 | 指南对不同建议给出不同证据等级，不能一概称强证据；没有统一最佳复习间隔 |
| [NCCE 教学法与 PRIMM](https://teachcomputing.org/pedagogy) | 预测、运行、探查、修改、创作；先读代码和逐渐撤架 | 保留代码阅读、调试、小修改和解释，减少开局从零写程序的负担 | 主要是学校编程教学背景，对成年 AI 开发者的效果仍需试点 |
| [Harvard Project Zero 思考惯例](https://pz.gse.harvard.edu/thinking-routines) | 通过稳定的小活动使学习者的想法可见 | 偶尔记录“原来怎样想、什么证据改变了想法” | 这是反思线索，不自动证明长期保持；本轮检索摘要可读，正文直开超时 |

两项 AI 教学研究给出重要的双向提醒：

- [Bastani 等，PNAS，2025](https://www.pnas.org/doi/10.1073/pnas.2422633122)：土耳其高中数学随机试验中，普通 GPT 辅助提升练习表现，但撤去工具后成绩低于无 AI 对照；教学护栏版本大幅缓解该负面影响，却未显示对应无辅助考试的显著正收益。**避免伤害不等于证明促进学习。**
- [Kestin 等，Scientific Reports，2025](https://doi.org/10.1038/s41598-025-97652-6)：194 名哈佛物理课学生的试验发现，精心设计的 AI 导师在所测内容上带来更高学习收益、用时更少。**有效的是特定课程内容、提示与教学设计的组合，不能泛化成任何聊天 skill 都优于教师。**本轮通过论文 DOI 搜索摘要及 PubMed 核查基本结论，Nature 正文直开受访问限制，未重新审计全文方法。

因此最适合作为 Surika 主轴的是“**提供支持，并根据实际表现逐步撤去支持**”。苏格拉底提问、检索练习、PRIMM、反思都作为可选活动，避免把多个理论名词堆成每课必须经过的长流程。

## 5. 产品定位与边界

比较三个候选方向：

| 方向 | 优点 | 主要问题 | 建议 |
|---|---|---|---|
| 通用的“什么都能教” skill | 使用范围大 | 内容、评估和反馈难以校准，容易退化为通用提示词 | 暂不作为首版承诺 |
| 仓库逆向推导 skill | 入口明确，贴近工作 | 与 rederive 重叠；没有仓库、基础不足的人难进入 | 作为可选活动 |
| AI 编程者的持续技术学习伙伴 | 延续项目目标，探索和系统学习均可容纳 | 需要真正做好续接、教学材料和证据记录 | 推荐主方向 |

**首批用户**：能借助 Agent 做项目，但对语言机制、代码行为和设计理由缺乏稳定理解的人。

**核心承诺**：带着问题来可以开始，不知道该学什么也可以开始；回来时接得上；得到的反馈说明自己在什么帮助下能做什么。

**首版内容范围**：沿用 Go 执行过程、变量与值、函数输入输出。通用教学规则可以不绑定语言，但不据此宣称所有学科已受支持。仓库只读取材建议作为第二个验证场景，不成为入口要求；它是相对于旧版“无任意仓库导入”的新提案，需要在转向决策里明确。

**不承诺**：自动形成准确能力画像、完全防止 Agent 代做、持续后台监督、跨所有宿主完全一致、仅凭 skill 保证代码安全执行。

## 6. 交互设计：一个入口，按需要选择活动

拟议入口是 `/surika` 或自然语言调用，具体调用语法由宿主决定。用户无需先选择“学习模式”。

| 用户表达 | 建议的第一步 |
|---|---|
| “我想弄懂这个” | 直接回应问题，给足必要背景，再邀请一个有意义的尝试 |
| “我不知道从哪里开始” | 提供一个很短的具体例子，以其反应决定下一步 |
| “带我理解这个项目” | 只读选择一条与目标相关的问题链，不一次扫描并讲完整个仓库 |
| “继续上次” | 读取当前摘要与相关记录，简述停在哪里，给出一个可继续的活动 |

一个推荐但不强制的闭环：

```text
当前问题或起点
    ↓
一个小目标＋必要背景
    ↓
解释 / 示例 / 预测 / 修改 / 推导（按需要选）
    ↓
具体反馈；卡住则增加帮助，顺利则减少帮助
    ↓
记录表现与帮助条件，留下下一步
    ↓
后续用新例子或延迟活动检查理解
```

示例：用户问“为什么函数里改了数字，外面的值没变？”如果已经能读程序，就围绕一个简单整数例子解释参数和值的关系，让用户改变调用或返回方式；如果连赋值符号都不熟悉，先示范几行的执行过程。理解整数例子后记录范围，不扩大为“掌握所有 Go 参数语义”。这里是交互设计示例，不是已经核验并发布的课文。

界面原则：默认短对话；用户可以要求直接讲、给提示、换例子、暂停或跳过。图示解释关系和变化，HTML 只用于确有交互价值的材料。需要正式观察独立表现时先说清条件，日常探索不强制每轮测验。不把兴趣问题立即转成题库。

执行开发任务与学习必须能区分：Agent 替用户写好的实现可以作为教材，但不记为用户独立完成。用户转回开发交付时尊重其意图，后续可另开学习活动，避免教学规则阻塞正常工作。

## 7. 技术方向：薄 skill、明确状态、必要工具

[Agent Skills 规范](https://agentskills.io/specification)允许 SKILL.md 搭配 scripts、references 和 assets；因此 skill 可以是一个有材料和小工具的包，无需把所有内容挤进一个提示词。规范的目录兼容并不保证各宿主的工具、权限和调用行为一致。

### 最小分工

| 层 | 职责 |
|---|---|
| 宿主 Agent | 模型、对话、文件访问、搜索和工具执行；实际权限由宿主控制 |
| Surika skill | 教学选择、证据规则、上下文续接、何时生成材料 |
| 随包内容 | 一小段 Go 路径、核验来源、活动说明、常见误解、反馈依据 |
| 用户学习目录 | 目标、相关经历、可修正判断、下次入口；不放进全局 skill 安装目录 |
| 可选实验工具 | 执行和返回真实结果，承担实际权限与资源约束 |

拟议包结构与状态结构分开：

```text
surika/                       # 可分发的 skill 包
  SKILL.md                    # 核心行为与按需读取规则
  references/                 # 教学策略与 Go 首段材料
  assets/                     # 记录和参考材料模板
  evals/                      # 行为评估案例与判断依据

<学习工作区>/.surika/          # 私有学习状态，首次需要时创建
  state.md                    # 暂定目标、当前问题、下一步、记录索引
  sources.md                  # 实际使用的资料、范围和核验时间
  records/                    # 关键经历与有范围的判断
  materials/                  # 按需产生的参考卡、图示和实验材料
```

先用 Markdown 和稳定记录 ID，不引入数据库、向量检索、知识图谱或多 Agent。摘要保持短小，按主题/ID 读取相关记录；记录数量增长到实际难以检索时再增加索引工具。首版使用单个会话写入同一学习目录，暂不设计多写者同步。

**一条有效记录的最小内容**：活动与时间、题目或代码版本、用户原始表现的必要摘录、获得的帮助、实际结果、有限解释、未确认之处、后续活动。仅有宿主聊天链接而无必要摘录时，换宿主可能无法复核；不能伪造完整历史。暂停或活动结束即保存小结，避免只依赖会话结束事件。

例如：

> 观察：用户在看运行结果前，预测了一个整数参数例子的输出，并解释了调用方值不变。帮助：此前看过一个相似示范。推断：开始理解该类简单例子；不同类型与延迟保持未确认。下一步：换一个函数返回值的例子。

用户修正偏好和目标时直接更新相应状态；若修正的是技术事实，记录分歧并核验，不能把用户或模型的断言自动变成事实。更正的判断应明确替代旧判断，后续不继续引用旧摘要。

### 必须显式处理的能力边界

- **有文件权限才能保证跨会话保存。**无写权限时提供可复制小结，并说明未保存；不能宣称已记住。
- **有来源才声称已核验。**网络不可用时可用随包、注明版本的材料；超出材料范围的版本性结论保持待核查。
- **有执行结果才声称已运行。**模型预测、用户报告和工具结果分别记录。
- **Skill 本身不是沙箱。**工作目录或临时目录不构成隔离；不能用“只运行安全代码”替代权限限制。
- **复习建议不是定时服务。**第一版在用户再次调用时提起相关活动，不承诺后台提醒。若未来需要提醒，交给宿主调度功能单独实现。
- **本地记录不等于全程本地。**记录被发送给宿主模型后受其数据路径影响；只加载教学所需内容，不默认上传整个仓库或全部历史。

执行方案建议先验证不依赖运行的解释、代码阅读、推导与记录闭环。应用版实验工具没有随 skill 保留；当实验确实必要时，再独立评估 Go 实验命令及其工具链、资源限制和隔离。没有等效约束的宿主不开放任意运行，并明确标记实验不可用。

### 清理后的实现边界

- 学习记录原则保留在 skill 的按需参考中；旧桌面状态的存储实现已经移除。
- 首段内容的来源与教学材料仍需重新检查具体规则和例子，不能假定旧 Demo 的内置目录已经审核充分。
- Go 实验执行不再随仓库提供；如未来需要，必须作为独立工具重新设计和验证。
- 桌面 UI、模型客户端及其实现决策保留在历史文档中，但不作为当前交付范围。

文件化记录会自然允许手动查看、复制和删除，这与旧版“无导出/删除 UI”的产品边界不同。无需专门开发导出功能，也不应为了复刻旧限制而阻止用户控制自己的文件。首次进入项目目录时说明保存位置及版本控制处理，避免把个人学习记录默认作为共享项目产物提交。

## 8. 先验证什么，再做什么

建议沿用原个人试点投入：3～5 次、每次约 15～25 分钟，约一周后再观察；这只是试点安排，不是最佳时长或间隔的科学结论。

先交付一个可运行的最小 skill 和已核验的 Go 小材料，覆盖三种使用：不知道学什么、带着具体疑问、跨会话继续。下一轮再验证有基础时的仓库推导。无需先写完整课程或搭建通用教学平台。

分开检查两类结果：

| 检查对象 | 方法 | 不能据此宣称什么 |
|---|---|---|
| Skill 行为可靠性 | 用固定情境检查：卡住会不会示范、要求直接解释是否尊重、无证据是否乱记掌握、纠错后是否沿用旧判断、无执行是否虚构结果、重开会话能否续接 | 不能证明学习者已经学会 |
| 学习者变化 | 观察其解释、修改、提出反例、所需帮助，以及延迟后新情境的表现 | 单人短试点不能证明普遍效果或因果优势 |

评估材料应有来源和判断依据；模拟学习者可检查行为，不替代真人学习试验。同一 Agent 自己教学再自己说“教学成功”不够，需要查看原始表现、已核验答案及反例。模型或宿主变更后重跑关键行为案例。

继续投入的信号：回到学习的成本低，下一步确实利用历史，出现新的解释或运用，帮助逐渐减少，用户愿意继续。需要修改方向的信号：总在生成材料而不发生学习、反复追问导致卡住、记忆误判反复污染教学、续接成本超过直接提问。

可以用普通 Agent 对话、teach、rederive 做小规模可用性参照，分别比较开始成本、帮助方式、续接与记录；不要重复用同一道题就宣称某个 skill 有更高学习增益。

## 9. 建议的决策顺序

1. 确认 skill-first 是下一阶段的主要交付方向；原桌面 Demo 暂停扩展。
2. 保留 AI 编程者与 Go 小范围试点，不同时扩大到全学科。
3. 确认“可以直接解释、逐渐撤架、用户可切换”的教学原则；不采用永不透露答案的硬规则。
4. 先完成教学和文件记忆闭环；独立决定 Go 实验工具的接入，不以默认 Shell 执行代替旧边界。
5. 依据真实使用结果再决定是否扩展仓库学习、语言、调度或 UI。

以上是建议顺序，不是已经批准的需求变更。本轮只新增这份研究提案，保留现有产品决策、ADR 和实现。
