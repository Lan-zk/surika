# Surika 产品决策与讨论入口

> **当前范围（2026-11-22）：** Surika 已收敛为教学 skill v0.5.0，参见 [ADR 0007](adr/0007-skill-workflow-and-visual-design.md) 和 [SKILL.md](../skills/surika/SKILL.md)。下文桌面应用、应用管理工具链、记录导出／删除限制及固定可视化模板属于历史决定，不再约束当前实现。当前采用通用设计文档指导按需生成材料，用户可自由切换学习与开发。


整理日期：2026-11-12。依据本次用户讨论及随后确认的调研结论。这里记录决定与边界，不代表功能已经实现；后续回答到达时更新对应条目。

## 目标与首批用户（已确认）

**帮助借助 AI 编程的人，逐步建立系统、可迁移的技术理解，让完成开发任务的能力伴随着自身能力的增长。**

首位用户为项目发起者，首批面向相似的 AI 开发者：能够借助 Agent 参与项目，但无法清楚判断自己的语言理解与知识缺口。应用承担识别起点和安排学习的职责；不要求学习者知道该学什么、知道自己不知道什么。

项目经历是需求来源，不意味着必须接入仓库或要求用户提交 PR。此前围绕真实改动启动的建议已被后续讨论修正，不作为当前入口要求。

## 产品定位（2026-11-12 修订，已确认）

**有持续记忆、可信知识依据和教学能力的学习空间。用户可以自由探索，也可以让应用带路；交流与实践逐渐积累成自己的理解。**

课程路线是可调整的支持方式，不是应用的唯一主线。有问题时围绕问题学习；没有问题时提供起点；探索偏离路线时允许继续或返回；需要系统补齐时提供连贯路径。用户无需先明确完整学习使命才能开始。

自由涉及问题、方向、节奏和表达方式，不取消知识核验与执行边界。历史记录帮助估计下一步，不意味着能够准确计算能力；讲解按内容与困难选择文字、例子、图示或实验，不强制大图少字、HTML 或固定课长。

已确认允许探索 Go 中尚未编写成课程的问题：优先使用已审核内容；新问题先查可靠依据，再组织解释与实验建议。无法确认的结论保留疑问；查到资料、生成讲解与正式审核分别记录，临时生成内容不自动成为正式教材，也不自动形成掌握判断。

后续已确认允许为探索中的问题生成 Go 短实验，并在受限本地环境中运行。动态实验与内置课程代码接受相同执行限制，不开放任意项目导入和第三方依赖。来源核验支持教学结论，编译运行提供行为观察；运行成功不自动证明解释正确、运行安全或学习者掌握。

本次仅借鉴 teach / eli5 的教学与表达思想，没有执行这两个技能。Go 连续课程小样用于验证教学能力，不限定整个产品形态；也未据此批准首版支持所有主题或任意代码执行。

## 已确认的学习原则

- 学习意味着理解和行动能力发生可以保留、用于新情况的变化；掌握是明确范围与支持条件下的有限判断，不是永久标签。
- 探索、理解、联系和运用是主体；从学习活动中积累证据，必要时补充短测验，不以考试过关组织每个单元。
- 反馈说明“现在能做什么、哪里仍需支持”；不要求人人以同一种方式证明理解。兴趣与参与感值得观察，但不能单独证明掌握。
- 应用主动带路；用户可以表达目标，也可以选择“不确定，先体验”。
- 边学边了解，不以全面水平考试作为开始前提；不能因一次回答推断整体水平。
- 需要带路时提供有依据的教学主线，允许自由探索与返回。讲解深度、活动次序、练习数量可以变化，不强制课程关卡。
- 用户可以追问、请求提示、补基础、加快、跳过和暂停；跳过不等于掌握。
- 单次学习围绕小目标闭环，不无限追溯基础。必要时缩小目标。
- 允许先预测再解释；允许回答“不知道”，随后提供必要帮助。
- 保留阅读、修改、补全、调试、解释及少量独立构造；不以大量从零手写业务代码为目标。
- 用新情境和延迟复测检查理解，区分提示后的正确表现与独立表现。
- 教学规则执行质量与学习者能力增长分别检验，不以流畅对话或测试全绿代替理解。

## 内容策略（已确认）

先做 Go。整体能力框架与一小段相连课程作为提供系统引导和验证教学能力的基础，明确目标、先修、来源、例子、常见误解、活动和验收依据；用户不必始终沿课程顺序学习。AI 的讲解和活动建议仍需可靠依据与应用约束。课外 Go 问题允许基于检索组织教学；检索来源、核验流程与正式内容准入方式尚待设计。

官方资料提供知识依据，既有课程提供组织参考；教学有效性仍需本项目验证。

2026-11-12 已确认首段能力目标：理解简单 Go 程序如何执行、值如何变化；能面对新的短程序预测结果、解释原因，并通过小修改检验判断。从程序结构、变量与赋值、函数输入输出建立联系，不假定这些基础已掌握。指针、切片和共享修改不自动纳入首段，待先修与样例设计后判断。

## 个人试点安排（已确认）

项目发起者亲自完成 3～5 次学习，每次约 15～25 分钟，结束约一周后做一次短复测。这是规模约束，不是已经验证的最佳学习间隔；若无法形成小闭环，应记录原因并调整课程，而不是强行赶进度。

观察学习者的解释、联系、探索、运用、纠错及独立程度，同时记录帮助、耗时和继续学习的意愿。试点可以安排明确的前后观察以检验教学，不意味着日常产品应像考试一样运行。撤回将即时和延迟新题表现作为主要通关条件的提案；复测可以结合新的探索或修改任务，而非固定试卷。

试点仅用于判断是否帮助这位学习者；观察任务、帮助边界、继续投入标准和审核流程尚未确定。详见[首段课程样本与试点计划](Go首段课程样本与试点计划.md)。

## 首版技术与交付边界（已确认，尚未实现）

| 决策 | 范围与限制 |
|---|---|
| Go + Viva 桌面应用 | 首先验收 macOS 学习闭环；是否更快尚无实现对比证据 |
| 自行配置模型服务 | OpenAI 兼容 Chat Completions，优先连接本机 Magpie 网关；实际兼容性待联调 |
| 模型设置 | Base URL、模型、可选 API Key；流式响应、取消和连接检查 |
| AI 与应用职责 | AI 提议活动，应用检查后执行；不得由一句模型评价直接改写掌握记录 |
| 本地 Go 实验 | 应用下载并管理固定版本工具链，不依赖或修改用户已有 Go；首次准备可重试 |
| 实验范围 | 内置课程与动态生成的 Go 短实验及其修改，适用相同执行限制；不开放任意项目导入与第三方依赖 |
| 学习记录 | 应用主动整理，用户可查看和修正；区分讲授内容、实际表现与推断，用于后续引导；保存在本机，未选定存储技术 |

本地执行不意味着模型也在本机运行；发送给网关的内容及其后续去向需要明确。运行超时、资源管理与权限隔离不是同一件事；隔离方案尚未核验。短程序范围不能替代隔离。

**MVP 排除项（已确认）：**暂不支持学习记录与参考材料的用户导出或删除。保留已确认的查看与修正能力；此次范围裁剪不意味着记录永久保留，也不取消内部纠错与过时推断的更新。
