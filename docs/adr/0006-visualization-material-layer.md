# 可视化作为按需生成的材料层

讨论交互式课程产品后确认：纯对话缺少可供双方操作的推理对象，预测与状态变化只能靠学习者想象；但固定课程界面与 [ADR 0004](0004-free-exploration-with-guidance.md) 的自由探索冲突。本决定只涉及学习活动中按需生成的材料，不恢复独立应用界面；"页面布局与学习记录的具体展示"仍搁置。

## 决定

- 图按**学习者此刻要做的推理**分类，不按学科分类：机制用执行步进器，项目用可定位、可下钻的依赖或调用地图，决策用权衡表与故障时间线。项目学习不新造第三种图。
- 可视化**按需生成**，不是常驻界面；没有学习者要做的预测、判断或定位就不生成，图的数量不代表学习进度。
- 模板与数据分离：模型只生成状态数据，模板负责渲染；数据必须来自可复核来源（实际运行、实际解析或真实记录），做不到就标为推演或改用文字。
- 每张图声明抽象层次与失效边界，并能降级为 Markdown 表。
- 首个实现是 Go 执行步进器（`skills/surika/assets/stepper.html`）与数据校验脚本；不建通用可视化引擎，不为未验证的主题预先建模板。

## 后果

- 需要维护模板与校验脚本；宿主不能渲染 HTML 时体验降级为表格。
- 生成的数据若未实际核对，会比没有图更有害；生成流程强制先运行或先解析。
- 学习地图（状态层）不纳入本决定：其数据源（`state.md` 与 `records/`）与展示方式仍待设计。
- 学习效果仍需试点对比，模板存在不等于可视化优于文字。

## 修订：2026-11-22

首个执行步进器验证后补齐另两种图，仍不建通用可视化引擎：

- `assets/flow.html`（请求旅程）与 `assets/map.html`（依赖 / 影响地图）落地，与步进器共用 `stepper-check.mjs`，按数据块的 `type` 分派校验。
- 数据契约按图固定：步进器为 `steps/frames/heap`；旅程为 `nodes/edges/steps`（边有 `kind/bow/lo`，步有 `ms/payload`）；地图为 `layers/nodes/edges/impact`（边有 `when`，影响面有 `origin/change/expected/notes/predict/summary`）。
- 设计判断独立为[教学可视化设计契约](../../skills/surika/references/DESIGN.md)：图形语法、教学循环、动效、版式与验收清单。模板是契约的参考实现，冲突时改实现或在契约记录例外。
- 地图模板采用固定四列分层网格，是该参考实现的布局选择，不是通用图布局；地图只承担定位，机制下钻到步进器或代码材料。
- 三个模板均在浏览器实测过预测路径、键盘操作、减弱动效与窄屏；教学效果仍未验证，"是否优于文字"仍待试点对比。
