# Surika 学习记忆结构提案

日期：2026-11-12。状态：原则已确认，具体结构与实现仍为提案。用户确认主动整理、可查看修正的学习记录，以及“经历可追溯、观察与推断分开、整理结果可修正、教学按需取用”。四类职责是当前结构建议，不意味着已确定数据表、服务划分或处理流程；见 [ADR 0005](adr/0005-evidence-based-learning-memory.md)。

## 文章核查与适用边界

一手来源：[Anthropic — The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)，2026-11-06。

文章区分原始日志、记忆笔记、组织后的表示和注入上下文；后台整理可回查来源、纠错与合并。实验中 wiki 的收益依任务而异，也可能膨胀；有些任务搜索与 wiki 配合优于单独 wiki。记忆策略的收益依赖模型，僵硬筛选规则可能适得其反。

以上是 Agent 任务实验，不是学习者掌握模型的验证；不能推出特定分层对 Surika 已有效，也不意味着必须引入图数据库或后台持续整理。文章中的原始日志可用于核对经过，但在教学中，日志包含教师和学习者的错误陈述，不能当成领域知识真值。

## 已确认的需求

- 应用主动整理，不要求用户每次填写笔记；用户可以查看和修正。
- 记录理解、尝试、疑问与联系，服务于后续教学。
- 区分“应用讲过”“用户自己表现过”“应用推断”；推断不是固定能力标签。
- 自由探索与连贯引导并存，不能只围绕课程完成度组织记录。
- MVP 暂不支持用户导出或删除学习记录及参考材料；查看、修正和内部纠错仍保留。

## 建议先区分四类职责

| 职责 | 内容 | 不应承担的角色 |
|---|---|---|
| 原始经历 | 用户原话、示例及版本、修改、运行结果、帮助和反馈的先后 | 自动认定其中陈述都正确 |
| 有依据的观察 | 某次解释、实验或纠错表现，关联原始经历与支持条件 | 从一次表现推广到整门技术 |
| 整理后的学习记录 | 目标、偏好、重要理解、联系、未解问题与有范围的能力推断 | 覆盖掉反例、永久保留过时结论 |
| 本次教学上下文 | 与当前问题有关的目标、近期观察、疑问和索引 | 每次加载全部历史，或代替完整证据 |

这些是逻辑职责，不要求四套存储服务。原始经历与观察可以先用同一存储中的不同记录表达；学习记录与本次上下文是可重建的整理结果。具体存储方案待定。

## 教材知识与学习者记忆须分清

“Go 的某条规则成立”需要规范、资料或合适的实验依据；“学习者理解这条规则”需要其实际表现。两者可以关联，但不能互相代替。

概念解释、参考卡和可运行实验是教学材料；某人看过、提出问题、修改或理解它的经过是学习经历。生成了十份解释不能推导为掌握十个概念。

## 事实、推断与建议分开

示例（用于说明结构，不是实际用户记录）：

- **观察**：在看到运行结果前，用户正确预测了一个简单整数参数示例，并说明理由；期间查看过语法参考。
- **有限推断**：对该类调用已有理解迹象；其他类型和延迟保持尚未观察。
- **建议**：后续可以换情境探索，不强制重复相同讲解。

不能压缩成“已掌握 Go 参数传递”。同样，用户说“不太懂”是自述事实，但具体缺口仍需要澄清；用户纠正偏好可以更新偏好，用户对语言机制的断言仍需要知识核验。

## 整理与纠错建议

1. 学习过程中优先保留必要经历，及时吸收用户的明确修正；不为整理而打断每次互动。
2. 在适当边界整理相关内容，回查原始经历，合并重复，保留反例与未解冲突；触发时机与预算待设计。
3. 整理结果关联支持它的来源；修改推断时同步更新依赖它的摘要和下次建议，不改写过去发生过的事实。
4. 用户已明确将导出与删除排除在 MVP 之外；暂不为此实现导出格式、删除流程或派生记录删除传播。可追溯不等于永久保留；后续若加入删除，再设计相关派生记录失效或重建机制。MVP 的内部纠错仍需更新受影响的摘要与建议。
5. 会话开始只取当前相关内容；缺依据时回查经历或知识来源，不把旧摘要继续总结成更确定的结论。

## 首版应检验的问题

- 换一次会话，能否继续已有探索，而非重新询问全部背景？
- 是否误把讲授、赞同或提示后答案记成独立理解？
- 用户修正后，下次是否还会受到旧推断影响？
- 不同情境出现相反表现时，是否保留范围差异而非强行合并？
- 找不到证据时，能否承认“未观察”，而非默认不会或已经会？
- 整理与检索是否确实帮助教学，而非只是增加记录数量和模型消耗？

先检验这些行为，再确定文件格式、关系表、索引、向量检索或 wiki 的必要性。不把记忆生成能力等同于教学诊断能力。
