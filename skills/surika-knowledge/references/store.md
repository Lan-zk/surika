# 个人记录工具

使用本包的 [knowledge.py](../scripts/knowledge.py)，需要 Python 3.9 或更新版本。以 skill 目录为基准解析脚本路径；保留用户的当前工作目录。以下示例中的 K 代表该脚本的完整路径。

| 操作 | 命令 |
|---|---|
| 查摘要 | `python3 "$K" search 支付 渠道` |
| 浏览下一页 | `python3 "$K" search --offset 8` |
| 看正文与当前版本 | `python3 "$K" show ID` |
| 保存新记录 | `python3 "$K" add --file 草稿.md` |
| 修正原记录 | `python3 "$K" update ID REV --file 修正稿.md` |
| 找出引用它的其他记录 | `python3 "$K" search --ref ID` |
| 删除已确认的记录 | `python3 "$K" delete ID REV` |

库位可用命令前置参数 `--root 目录` 指定。默认从 `~/.surika/records/*.md` 的原件检索，多个检索词须同时命中；没有结果时可缩短检索词。返回 JSON，默认最多八条摘要，total 为总数。已有 Markdown 同样可检索。没有记录时查询返回空结果，首次保存才建目录。项目的 state.md 和旧格式文件仍可按原方式就地读取。

新增或更新时也可从标准输入传入完整 Markdown。第一行以 `# ` 开头，是可独立阅读的陈述。正文按需保留来源片段、表现或条件，例如：

```markdown
# 用户自述曾负责订单重试任务的实现，策略由同事制定。

来源：本次项目复盘中用户说“同事定了重试策略，我实现了任务”。
```

工具返回的文件名主体是稳定 ID，改标题时保留文件名。记录间的关系用 `[说明](./ID.md)` 引用，在同一句说明谁发现了什么联系。写入工具检查目标是否存在。添加前检索已有记录，重复请求或保存结果丢失时先核对。修正或删除前检查反向引用及依赖旧说法的摘要。删除被引用的记录时先处理相关陈述。版本冲突时重新读取后再应用仍适用的修改。

用户可以用文本编辑器查看或编辑这些 Markdown；保存后的检索直接反映原件。与 Agent 同时编辑同一条时宜先完成一方的修改。没有 Python 时，按同样的约定使用宿主文件工具，修改前重读并检查引用。
