# Surika 可视化设计

目标有两个：形成可辨识的 Surika 风格；让关系、状态和思路通过视觉表达出来。本文提供设计语言，不规定页面模板、数据格式或教学关卡。用户明确的呈现偏好优先，布局、技术和图形按当前问题选择。

## 从思路到图

先确定用户要看懂什么，再选择承载它的视觉结构。图示可以直接解释，也可以用于探索，不必附加练习。HTML 适合逐步揭示、改变条件或反复观察；静态图已足够时保持简单。

| 要理解的事情 | 可采用的表达 |
|---|---|
| 值、执行位置或状态如何改变 | 状态前后对照、代码与状态联动、按需步进 |
| 请求、数据或事件经过哪里 | 流程图、时序图、泳道与路径高亮 |
| 谁依赖谁、改变会影响什么 | 分层关系图、局部聚焦与影响范围 |
| 条件为何改变选择 | 对照图、权衡表、参数变化与结果联动 |

这些是起点，不是图型白名单。让位置、连接、大小或状态变化承载信息；段落补充图中看不出的原因与边界。例如“参数按值传递”可画调用前后的两个独立值，修改其中一个时另一个保持不变，比把定义放进三张卡片更能解释机制。

去掉解释段落后，用户仍应能从图中辨认关键关系或变化。若图只是文字容器，重新选择表达方式；复杂内容可以分层展开，不以少字牺牲必要条件。

## 品牌与视觉风格

视觉基调是安静、清晰、带有温度的技术笔记：暖白底、深绿标识、克制的线条和留白。延续狐獴品牌“逐渐帮助人建立理解与判断”的方向，主题内容优先于品牌装饰。

下面是默认配色起点，颜色职责保持一致；深色环境或用户偏好可适配，优先保证可读性。

| 用途 | 默认值 |
|---|---|
| 页面底色 / 内容面 | `#F7F5EF` / `#FFFFFF` |
| 正文 / 次级文字 | `#182D23` / `#56665C` |
| 品牌深绿 / 当前重点 | `#23452C` / `#1F6B57` |
| 重点浅底 / 分隔线 | `#E5EFE8` / `#D6DED7` |
| 需要注意的变化 / 错误 | `#8A5A08` / `#A2442D` |

正文使用系统无衬线字体，代码使用系统等宽字体；通过字号、字重和间距形成层级。主体文字默认 16px 左右，辅助标签也应清楚可读。优先留白和轻线条，圆角与阴影克制。颜色用于当前重点或有意义的差异，并搭配文字、形状或线型，不单靠红绿区分结果。

### 标识

使用随包的 [狐獴 logo](../assets/logo.png)，保持比例与原色，不重画、拉伸或用其他动物替代。通常在材料页首或页尾出现一次，与 `surika.` 字标并置；以约 24–32px 的小标识为起点，四周留白，主题标题优先。小尺寸失去辨识度时可只用字标。

品牌口号是 “Learn to think. Not just to code.”，适合封面或收尾，可省略。标识不作为水印、背景纹理或反复出现的装饰。生成独立 HTML 时可内嵌原图数据以便携带；使用邻接文件时一并交付，避免依赖 skill 安装目录的绝对路径。宿主不支持图片时用字标，不因此阻塞交付。

## 流程（flow）可视化

先找到主体、方向和关键转折，再布置节点。主线沿阅读方向展开，分支写触发条件；返回、异步和并发关系有不同表达时配简短图例。箭头注明传递的东西或关系，节点说明职责，避免只有框名和无语义连线。

- **过程：** 用位置与路径表现先后，用状态或载荷变化解释每一步的意义。稳定节点位置，让用户跟得上当前对象。
- **因果：** 区分“先发生”和“导致”；耗时、比例和规模有依据才按真实量绘制，示意值就明确标注。
- **并发：** 用泳道或并列分支表达并行，动画顺序不应暗示不存在的串行依赖。
- **复杂度：** 先呈现当前问题的主路径，相关细节可展开；大图可以局部聚焦，不为完整而把全系统同时铺满。

例如请求旅程不仅移动一个圆点，还应在关键位置体现“鉴权通过”“缓存未命中”或“返回结果”；若这些状态与当前问题无关，就保留更简单的路径图。

## 动效

动效用于帮助眼睛追踪变化：值变化时局部高亮，请求移动时沿路径连接前后节点，焦点转移时弱化旧对象。每次推进要让人看出发生了什么；静态关系不必为了活跃而运动。

局部反馈可从 150–300ms、路径演示从 400–800ms 起步，按内容密度与用户节奏调整。这是节奏建议，不是验收阈值。需要阅读的步骤由用户推进，连续演示提供暂停和重播。避免与讲解无关的循环、粒子和反复入场。

尊重 `prefers-reduced-motion`；用静态高亮与直接切换保留信息，关闭动画后仍能理解状态和关系。

## 交互

交互围绕用户要观察的变化设计：查看前后状态、选择路径、改变一个条件、展开细节。操作附近直接呈现结果，当前条件和状态可见；重新尝试应容易。可以只有阅读，没有互动。

预测题只在用户愿意练习且对理解有帮助时加入，允许跳过和直接看解释；反馈指出对应的状态或关系，不把点击正确等同于理解。不强制导出答题记录或完成整段流程。

控件有清楚名称与可见键盘焦点，重要信息不只放在悬停里。窄屏重排或允许图局部滚动，保持文字可读；浮层能退出，操作不被遮挡。

## 实现与交付

根据宿主能力现场实现，不依赖预置 HTML 模板或专用校验器。简单材料优先轻量 HTML、CSS 与 SVG；复杂表达可以使用宿主已有工具或合适库，新增依赖遵循宿主与用户授权。用户未要求的导航、设置、评分和日志系统不随材料扩展。

技术数据沿用主 skill 的核验要求；简化模型、假设和推演在对应位置注明。内容足够时给出简短来源与边界，不堆叠无关元信息。

交付前按实际内容检查：图是否表达了关键思路，标识与文字是否清楚，主要操作是否有效。可用浏览器时检查关键交互和窄屏；无法验证时说明实际检查范围。告诉用户打开方式；宿主无法展示时，用简图、状态表或文字表达同一核心内容，无需保持完全相同的交互形式。
