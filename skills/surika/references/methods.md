# 方法依据

以下是教学设计与证据方法的依据，不是 Surika 已有效的证明，也不要求授课时加载原论文或向用户展示方法名称。

- [认知学徒制 — Collins、Brown、Holum](https://www.aft.org/ae/winter1991/collins_brown_holum)：组织示范、指导、支架、表达、反思与探索。不能简化成永不讲答案。
- [逆向设计 — McTighe、Wiggins](https://files.ascd.org/staticfiles/ascd/pdf/siteASCD/publications/UbD_WhitePaper0312.pdf)：让目标、观察依据与活动一致。目标可局部、暂定，不要求先完成使命访谈。
- [形成性评价 — Black、Wiliam](https://www.bates.edu/research/files/2018/07/Black-Wiliam2009_Article_DevelopingTheTheoryOfFormative.pdf)：利用表现改变下一步教学。收集记录和评分本身不等于促进学习。
- [IES 学习实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)：检索、间隔、示例与练习交替等策略，各项证据等级不同；不存在本 skill 已验证的统一复习周期。
- [学习与表现 — Soderstrom、Bjork](https://bjorklab.psych.ucla.edu/wp-content/uploads/sites/13/2016/11/soderstorm_ra_learningvsperformance.pdf)：当场顺利不等于长期保持或迁移；当场困难也不直接证明没有学习。
- [NCCE 编程教学指南](https://teachcomputing.org/pedagogy)：代码阅读、示例、PRIMM 和逐渐撤架的实践参考，学校教学情境不能直接证明成年 AI 编程学习的效果。
- [Notional machines — Sorva](https://doi.org/10.1145/2483710.2483713)：综述初学者理解程序运行过程的困难，包括编程误解研究；主张把所教的抽象机器作为明确的学习目标，某些编程范式可用不同抽象层次的多个抽象机器。研究背景是入门编程教学。
- [质量属性工作坊 — Barbacci 等，SEI](https://www.sei.cmu.edu/library/quality-attribute-workshops-qaws-third-edition/)：在架构形成前用排序、细化的场景找出驱动设计的质量属性；场景至少有清楚的刺激与响应，并有响应度量。这里只借用场景写法，不要求举办工作坊。

实施检验与学习效果检验分开：先看是否尊重用户方向、合理调整帮助、准确记录证据，再用真实学习和后续运用判断是否受益。不要用模型自评、产物数量或对话流畅度证明掌握。
