# 知识处理与学习记录

记录用于积累专业经验、调整教学起点和续接问题。用户明确指定的目录优先。个人技术背景、项目经验和可跨项目复用的学习记录默认读写用户主目录下的 `~/.surika/`。仅服务于当前项目的学习进度和材料沿用工作区的 `.surika/`。按请求选择相应目录，避免重复保存；已有项目记录仍可就地续接。首次有值得延续的内容时说明保存位置，用户拒绝就只保留对话。一次短问答无需建档。

个人知识的检索、保存、修正和删除沿用[个人记录工具与格式](store.md)。项目内的学习进度继续就地维护。

## 读取与保存

当前上下文够用时直接回答。需要历史背景时，可按项目、主题或相关约束检索索引和记录，只取相关摘要；短记录也可直接读取。当前意图优先；未知格式先理解，不覆盖已有文件。需要作能力判断时回到原始表现，摘要只能作为线索。

- `state.md`：当前方向、未解决的问题、相关记录链接，以及用户明确表达的偏好。保持简短。
- `records/`：只记对后续有用的经历，包括值得保留的技术自述、项目职责与取舍，或任务与版本、用户必要原话或行为、获得的帮助、实际结果与判定依据，以及支持什么有限判断。用户自述和观察分开，缺少证据就写未知。
- `materials/`：需要保存的图示或 HTML；材料本身不是学习表现。沿用日期与主题命名，避免覆盖。

已有记录且出现值得延续的变化时及时更新，不强制每次总结。用户修正目标和偏好时更新；旧判断被新证据推翻时标注替代关系，避免旧摘要继续主导教学。无需收集全部操作日志，也不要求用户从 HTML 复制 trace。

## 陈述与关系

- 交付一项陈述时，写清对象、内容、来源及影响含义的条件。摘要可以独立阅读，保留“用户自述”“同事选型”“提示后完成”等会改变归属或能力判断的限定。
- 保存关系时，引用两端记录并写明为什么相关、谁提出了联系，以及必要的适用边界。只保存有依据、以后有用的关系。
- 同一职责被记错时纠正原记录并检查相关摘要和链接；不同约束下的选择可以并存。新的独立表现可以补充为进展。删除时清理相关索引与派生摘要。
- 索引项用简短陈述和记录的相对链接，供人阅读和工具定位。跨项目查询个人知识时从个人目录检索；跨宿主复用需能访问同一目录。

## 用户控制

用户可查看、修改和删除记录。只保存必要片段，不自动提交、同步或上传。位于 Git 仓库内时检查是否忽略，未忽略则说明可能被提交，修改忽略规则遵循用户授权。无写权限时说明未保存，可提供简短续接摘要。复习建议不等于后台提醒；本地文件被宿主模型读取也不等于全程本地处理。
