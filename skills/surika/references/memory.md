# 学习记录

记录帮助下次接上问题，不是成绩单。用户指定的目录优先，否则用当前工作区 `.surika/`；与 skill 安装目录分开。首次有值得延续的内容时说明保存位置，用户拒绝就只保留对话。一次短问答无需建档。

## 读取与保存

先读已有 `state.md`，再按当前问题读相关记录，避免加载全部历史。当前意图优先；未知格式先理解，不覆盖已有文件。需要作能力判断时回到原始表现，摘要只能作为线索。

- `state.md`：当前方向、未解决的问题、相关记录链接，以及用户明确表达的偏好。保持简短。
- `records/`：只记对后续有用的经历，包括任务与版本、用户必要原话或行为、获得的帮助、实际结果与判定依据，以及支持什么有限判断。用户自述和观察分开，缺少证据就写未知。
- `materials/`：需要保存的图示或 HTML；材料本身不是学习表现。沿用日期与主题命名，避免覆盖。

已有记录且出现值得延续的变化时及时更新，不强制每次总结。用户修正目标和偏好时更新；旧判断被新证据推翻时标注替代关系，避免旧摘要继续主导教学。无需收集全部操作日志，也不要求用户从 HTML 复制 trace。

## 用户控制

用户可查看、修改和删除记录。只保存必要片段，不自动提交、同步或上传。位于 Git 仓库内时检查是否忽略，未忽略则说明可能被提交，修改忽略规则遵循用户授权。无写权限时说明未保存，可提供简短续接摘要。复习建议不等于后台提醒；本地文件被宿主模型读取也不等于全程本地处理。
